## 风格方向样张（2026-10-11）

用户要求二维换成更有质感的风格，三维要和二维大体一致，三棱镜样稿要加强零件感。样张 `mockups/craft-directions.html`（截图 `mockups/shots/craft/card-A|B|C.png`，`node mockups/shoot.mjs` 生成），同一个场景「斜面小车经过光电门」，只换风格：

- A 纸本墨线：暖白纸面，深褐墨线 1.1 px，三档平涂，地面剖面线。
- B 冷灰实体：冷浅灰，四档明暗渐变，顶面亮、倒角高光、柔和投影，细线 0.7 px。最接近 Anatomy 浅色主题。
- C 暗色实验台：深色卡片，深灰金属，冷色轮廓光，强调色带微光。和原三棱镜样稿同一路。

三张共用的规矩：一个强调色（速度箭头），零件都有着落（底座和脚、铰链块、立柱带底座和夹块、旋钮、刻度尺的刻度从边缘长出、计时器屏幕和接口、线缆两端接在接口上），图里只有 θ 和 v 两个符号，名称和数值都放在卡片角上和底部。

判断：问题 1、5、6、7 出在基础图元和组件的默认样式上，改运行时就能让所有课件一起变好。问题 2、3、4 一半是默认样式（标签字重、电流点密度），一半是写课件的人（或模型）的选择，要靠规矩卡和排版检查。

## 统一评估：所有组件改成 B+ 要动什么

### 现状

- 画布运行时 `app/src/sim/runtime.js`（约 6400 行）：约 67 个 `v` 工具，其中约 35 个画实物。颜色写死 84 处 hex；已有 `enamelPath`、`steelDisk`、`steelRect` 三个材质函数，但只有少数工具在用。
- 12 个 React SVG 组件（Circuit、ForceDiagram、Plot/charts、Instrument、Wiring、EnergyLevels、GasBox、GasTube、Fringes、TickerTape、Sim）：大多已经读 `app/src/theme.ts` 的调色板，写死 hex 只有十来处。
- 字体：`styles.css` 已经有四种角色（正文 Noto Sans SC、等宽 JetBrains Mono、物理符号 Source Serif 4 斜体、标题 Noto Serif SC），和样张一致。样张只多了读数用的 Inter 细体。

两条渲染路径（画布、SVG）各画各的，这是风格不统一的根源，也是这次要收口的地方。

### 架构：三层

1. **令牌层**：在 `theme.ts` 加 `material` 一组，亮、暗两套主题各一份。内容就是样张里的 `t`：
   - 四档实体明暗 lo / mid / hi / dark，每档有顶面、正面渐变两端三个值；
   - 线：轮廓 0.7、辅助 0.55、印字色、标签色；
   - 倒角高光、接触影、环境影；
   - 屏幕、线缆、指示灯；
   - 强调色仍然是物理量颜色（速度、力……），不新增颜色。
2. **图元层**：新建 `app/src/craft/`，用 TS 写一套纯函数，输出「形状列表」（矩形、路径、渐变填充、文字）。下面接两个很薄的后端，一个画到 Canvas 2D，一个输出 SVG。画布运行时和 SVG 组件调用同一套图元，保证同一个物体在两边长得一样。三维以后也读同一组令牌（材质灰度、强调色、印字贴图）。
   - 实体：`slab`（带顶面和倒角的块）、`prism`（斜面楔块）、`disc`（轮子、滑轮、圆柱端面）、`tube`（管、导线截面）。
   - 零件：底座和脚、立柱和夹块、铭牌印字、刻度尺、屏幕、指示灯、线缆和接头、旋钮。
   - 影：接触影、环境影。
   - 标注：箭头（头部收在线端）、角度弧、物理符号、等宽小字。
3. **使用层**：`v` 工具和 SVG 组件只调用图元，不再自己配色。课件的写法和参数不变，旧课件自动换装。

## 画面规矩（B+ 材质版定稿，2026-10-11）

用户认可材质版。规矩如下，令牌在 `app/src/craft/tokens.ts`：

- **视角**：正视图加一条顶面带。顶面带画在物体自身高度之内，不改变物体的占位和接触点，角度、长度照常可量。
- **光照**：光从上方来。顶面最亮，顶边一道白色倒角线；正面从上到下渐暗，近地处压暗；底边一道很细的反光。
- **材质**：铝（导轨、滑轮，拉丝）、喷漆钢（斜面、台面、墙）、亮钢（物块、小车车身）、橡胶（轮胎、脚垫）、深色件（光电门、极板、遮光条）、铜（接线柱，唯一的暖色）、玻璃（透明，只画边缘高光和反光条）。颜色只有冷灰，物理量颜色另算。
- **轮廓线**：小零件和要清楚的边用深线 0.9 px；面积大于 1600 px² 的物体用浅线 0.75 px，形状靠明暗托出来。
- **影子**：物体放在台面、小车、物块上时，接触处有一道贴地影；悬空的不画。大件底下可加大范围的淡影。
- **大面**：中部留给力和速度箭头。细节（端盖、螺丝、铭牌）只放在角上和边上。
- **强调**：同一时刻只有一个地方用强调色（例如挡光时光电门的指示灯）。物体永远是背景，物理量压在最上层。
- **外壳**：展台用冷灰渐变加大范围柔和投影；主读数用 Inter 细体。

### 答案严格核对、Motion NaN、器材补齐（2026-10-13）

- 答案核对：`scripts/answerkey.ts` 的数值项改成和 answers 里的数值一一配对（二分图匹配，一个值不能同时满足两项），不再是「全文出现过就算对」。新增 `answerkey.test.ts` 5 个测试。重核：旧 bank 可核 61/75，1 项不符（gd25-06「(2)④ B-I 图线斜率」）；bank2 0 项不符。
- `<Motion>` NaN（gd25-09）：求解器没问题。Worker 第一版只写了 `charge` + `fields`，没写重力，粒子竖直方向不动，靠 `y` 的事件永远不触发，读数成了 NaN。把同一过程补上 `forces` 重力后，落板时刻、反弹、碰后换电量、两次落点都和手算一致。
  - `motion-fields.md` 写明重力不会自动加，带电小球要再写 `forces`；附「碰板反弹 + `charge` 用状态量换电量」的例子。
  - `validate.ts`：`read` 用到的事件在初始参数下一次都没发生时提醒「读数是 NaN」；带 `charge` 没写 `forces` 的，提醒里加上重力写法。整库扫描无误报。
  - `fields.test.ts` 加 2 个测试（重力 + 电场 + 反弹 + 换电量的数值；提醒出现与消失）。
