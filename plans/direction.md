# 方向：课件库全面转向为"一节课"服务

（2026-10-22 与用户约定）这份是当前方向的总纲。旧的方向文档（`plans/pre-3d.md`、`plans/craft.md`、`plans/cloud-handoff.md`）保留作记录，和本文冲突时以本文为准。

## 一、为什么转

库原来的定位是"一道题一页"：一份 `.md` 课件对应一道高考题，写参数、问题、`<Sim>` 动画，主要给模型批量生成。这条线已经做到能用：渐进式文档、校验、排版检查、B+ 材质、`bin/genui` 工具链。

动量单元的 6 节课（第 1–5 节、进阶 A）却全部写在 `mockups/` 里，用手写 canvas 和一个独立的播放器 `mockups/momentum/shell.js`，没有用上库。结果是：

- 画面比库差。库里有带材质的 `v.cart`、`v.ball`、`v.spring`，带符号校验的 `v.vec`，自动避让的 `v.label`；`mockups/` 里是平涂方框和手摆标签。
- 两套画法、两套调色板并存（见第四节）。
- 课件是网页代码，不是纯文本，不能校验，也不受 CLAUDE.md 里"只加不删"的兼容规则保护。

2026-10-22 的样张证明两边能接上：在播放器里叠一个沙箱 iframe 跑库的运行时，第 4 节"轻车撞重车"那一步的小车和速度箭头改由库来画，和下面的柱子逐帧同步，亮色、夜光都正常（样张在会话临时目录，未进仓库）。

## 二、目标形态

**库服务于一节完整的课。** 一节课写成 `lessons/` 里的一份纯文本文件，播放器、作答、结论链、小测都是库里的组件，画面用库的运行时。

- "一道题一页"的格式保留，现有课件和题库照常校验（只加不删）。它以后也是一节课里的一块：例题、小测、作业可以直接引用。
- 每节课仍先写规格（`plans/lesson-*-spec.md`，按 `plans/lesson-design-standard.md`），课件从规格写出来。
- 写课的人只写文本，不写网页代码；物理计算写在课件里由库来算、来校验，不在播放器里另算。

## 三、要往库里加什么

只加不删：已有组件的新属性一律可选；全新组件按 CLAUDE.md 的兼容规则进快照。下面是从 `mockups/` 里已经验证过的做法整理出来的清单，名字和属性在第五节阶段 1 的规格里定。

### 1. 分步课（播放器）

| 能力 | 现在在哪 | 说明 |
|---|---|---|
| 幕、步、句 | `shell.js` 的 `GRAV.act`、`steps`、`beats` | 一句一句推进；`gateAt` 卡住不让往下走；`play` / `playAt` 讲到某句才开始播 |
| 题板布局 | `layout: 'answer'`、`tall` | 左画面右作答，或只有作答区 |
| 选择题 | `GRAV.ui.choice` | 固定反馈、三级提示、错两次给答案 |
| 先锁定预测 | 各课 act 里的 `guess` | 选了就锁定、不判对错，讲解时按学生选的那项给检查结果 |
| 演算行 | `GRAV.ui.work` | 一行一行出现的算式和旁注 |
| 定义卡 | `.def` 卡片 | 名称、注意、出处分行 |
| 结论链 | `board.js` 的条目（`at`、`under`、`title`、`ok`、`mask`） | 顶部推理链 + 浮层；回忆时遮住关键词 |
| 小测、作业 | 各课 act7 | 7 题一组，结果页可跳回看 |

结构上的难点：库现在规定"只有 `<Sim>` 和 `<Figure>` 有内容体，其他组件自闭合"，分步课的幕和步要装下别的组件，需要新的嵌套写法。这是阶段 1 规格里第一个要定的问题。

### 2. 画法（运行时 `v` 工具）

- 人：站、推、抛三个姿势，冰刀；宇航员（头盔、背包）。动量课第 3、5 节和进阶课都要用。
- 火箭（分级、舷窗、尾翼、尾气）、船（甲板、吃水）、水面。
- 小车的碰撞面：磁体、橡皮、魔术贴（第 4 节全靠它分三种碰撞）。
- 核子团（N 个核子挤成一个核，进阶 A 用）。
- 画面里的动量、动能柱子（库里有柱状图组件，还没有能放进动画画面、随时间变的版本）。

2026-10-21 的"画面样张"（会话临时目录，未进仓库）给过人、火箭、船、粒子的画法方向，进库时按 B+ 材质重画，不照搬。

### 3. 动效（2026-10-22 用户定）

物体怎么动必须按物理算，不加缓动。只加在运动之上的修饰：

| 动效 | 定 |
|---|---|
| 碰撞瞬间的压缩形变 | 要 |
| 接触点一圈短线 | 要 |
| 整车频闪残影 | 不要（库里已有的频闪点 `v.strobe` 另说，用时再看） |
| 速度箭头从零长出来 | 不要 |
| 火箭喷口的金色火焰 | 保留 |

## 四、规范统一

现在有三份规范，各管一块，互相有出入：

| 规范 | 在哪 | 管什么 |
|---|---|---|
| 教学 | `plans/lesson-design-standard.md` | 一节课怎么组织：规格六样、问题线、预测、结论区、难度梯度 |
| 组件 | `docs/`（L0 `index.md`、L1 卡、L2 参考） | 课件怎么写、每个组件的属性 |
| 画面 | `plans/craft.md` 的画面规矩、`docs/ref/sim-craft.md` | 材质、标签、器材对照表 |

统一要做的事：

1. **一套调色板。** 以 `app/src/theme.ts` 为准。`mockups/momentum/shell.css` 的值和它不一致：亮色 steel `#8d939b` 对 `#9AA0A8`、底色 `#f4f4f1`（暖）对 `#F1F2F5`（冷）；夜光 steel、graphite、card 也不同。播放器进库后只读 `theme.ts`。
2. **颜色只给物理量。** 蓝 = 速度，红 = 力和"不可能"，金 = 能量。`mockups/recoil/draw.js` 的冰面、水面用了速度蓝的淡色，违反这条，迁移时改成中性色。
3. **字体角色一套**：正文 Noto Sans SC、物理符号 Source Serif 4 斜体、读数等宽。库的小车标签现在用等宽字（"0.2 kg"），在课里显得重，阶段 1 一起定。
4. **教学规范进库文档。** 分步课组件的卡片里写清"什么时候先锁定预测""结论链一步最多几条"这类规则，出处仍是 `lesson-design-standard.md`；能自动查的（比如每步有没有落结论、提示是不是三级）做进校验。
5. **动效规矩**写进 `docs/ref/sim-effects.md`（上一节的表）。

## 五、三维

库原来的三维只走到样稿：`mockups/prism-3d.html`、`mockups/prism-b.html`（立体棱镜光路，canvas 上手写投影，B+ 材质），`app/src/craft/tokens.ts` 预留了"三维以后也读同一组令牌"。原计划"画面质量 → 三维试点 → 二维缺口"（`plans/craft.md`）停在第二步之前。

现在改成**在动量课上做三维实验**，原则：

- 只在空间关系本身是教学内容时用三维：平面里的斜碰（动量是矢量，要看两个方向）、爆炸碎片的方向、冰壶从侧面和俯视两种看法。一维碰撞继续用二维。
- 三维和二维用同一套令牌：材质、物理量颜色、字体，同一个物体两边长得一样。
- 先做实验样张，用户选了再进库。每个样张截亮色、夜光，电脑、手机宽度，并看手机上的帧率。

要比较的技术路线：

| 路线 | 好处 | 风险 |
|---|---|---|
| 继续手写投影（棱镜样稿的做法） | 不加依赖，能直接进沙箱运行时 | 遮挡、排序都要自己处理，复杂场景难写 |
| 打包一个三维库（如 three.js）进运行时 | 光照、阴影、相机都现成 | 运行时变大；沙箱 CSP 禁外部脚本，只能打包进去；B+ 材质要重新调 |

先做的实验（候选，阶段 4 前和用户定）：

1. 斜碰：两球在台面上斜着碰，动量矢量在平面里画成平行四边形，可转视角。为后面"动量是矢量"的进阶课准备。
2. 冰壶：第 1 节的冰壶，侧视和俯视切换。
3. 火箭：第 5 节的多级火箭分离，三维相机跟拍。

之后二维、三维在同一节课里混用，统一由分步课的画面区承载。

## 六、阶段

| 阶段 | 做什么 | 交给用户看什么 |
|---|---|---|
| 0 方向与文档 | 本文；旧方向文档标注 | 本文（2026-10-22 完成） |
| 1 分步课规格 | 组件清单、嵌套写法、属性表；第 4 节迁移方案（逐步对照 `mockups/collision/`）；调色板和字体定稿 | 规格文档，审过再动代码 |
| 2 播放器进库 | 分步课组件、校验、文档卡；第 4 节迁成纯文本 | 第 4 节新旧对照（亮、夜光，电脑、手机） |
| 3 补画法、迁其余课 | 人、火箭、船、碰撞面、画面柱子、两个动效；迁第 1、2、3、5 节和进阶 A | 每节新旧对照 |
| 4 三维实验 | 第五节的 2–3 个实验样张，比较两条技术路线 | 样张，用户选 |
| 5 二维三维统一 | 选定路线进库，规范统一写进文档 | 一节混用二维、三维的课 |

每个阶段都跑 `cd app && npm run verify`，全部通过才算完。

`mockups/` 里的课在迁移完成前保持可用，作为对照的标准答案；迁完一节，在 `plans/unit-momentum.md` 里改它的载体。
