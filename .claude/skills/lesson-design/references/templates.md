# 模板

三样东西：证据表与六档判定、课件要记录的数据、数值核对块。证据表和"课件要记录的数据"是规格里的两节，位置在标准第八节模板的"题目"之后、"自检"之前。这是对模板的补充，不是新规则。

```
## 题目
…
## 证据表
| 设计决定 | 依据 | 证据等级 |
## 课件要记录的数据
…
## 自检
…
```

## 一、证据表

### 写法

表头固定：`| 设计决定 | 依据 | 证据等级 |`。

- **设计决定**：规格里的一个具体选择，写到别人能指着规格找到它。"第 2 步用三种碰撞面并排"，不写"课程设计合理"。
- **依据**：
  - 引用外部材料的：作者年份、位置（页、节、表），**必须标"读了原文"或"只读摘要"**。
  - 依据是本规格自己的计算或脚本的：写 `check 块 <名字>` 或 `check_spec.py <条目号>`。
  - 没有依据的：写"教学经验，待核"，等级只能是"待真人测试"。
- **证据等级**：只能是六档之一，写在单元格开头。**一行一档**；同一决定有两种证据，写两行。
- 表之后写等级汇总（各档几条）和一张"待真人测试"清单，那就是请用户定、请用户安排的事。

### 六档的判定标准

| 档 | 什么情况可以标 | 不能标的情况 | 例子 |
|---|---|---|---|
| 已计算 | 规格里的数是 `check` 块算出来的，`check_numbers.py` 重算相符 | 手算、心算、没进 `check` 块的数 | 第 2 步橡皮一行的动量和 0.238、动能和 0.053 J |
| 已自动检查 | 脚本检查通过：`check_spec.py` 对应条目通过，或课件过了 `npm run verify` | 脚本"查不了"的条目；脚本通过只说明结构合规，不说明教学上对 | 错误想法清单每条填了四格 |
| 已盲评 | 新开的子代理只拿标准和规格，独立评过，且结论与该决定一致 | 评的人看过我们的结论或证据表；只有一份规格时排序没有意义，只能算逐条评 | 盲评认为第 4 步不是幻灯片，能填出"上一步留下的问题……" |
| 已模拟走查 | 子代理扮演带着某条错误想法的学生走过，该想法在规格说的那一步被推翻 | 把它当成真学生的选择率；一次走查不算多次 | 带着 C2 的"学生"在第 6 步选"A 停下"，第 6 步反馈后改答 |
| 有研究支持 | 一手研究的方法和数据与该决定一致，依据格写出作者年份、位置、读了原文/只读摘要，并写明研究对象与我们的学生有何不同 | 只有一个来源的做法（标"孤例"）；只读到别人转述；只引用设计标准 | 预测先锁定比只看演示效果好（Crouch 等 2004，只读摘要，美国大学生） |
| 待真人测试 | 以上都没有，或只有弱的；或已排进 `user-test.md`，结果还没出 | — | 预估首答正确率 40%；"撞人的一方总会停下"这条错误想法确有学生持有 |

说明：

- "只读摘要"的引用仍可标"有研究支持"，但汇总时和"读了原文"的分开数。
- 盲评和模拟走查是模型输出，不是真人证据。六档里没有"已真人测试"：真人测试做完后怎么标，由用户定（本技能不增加档位）；在那之前，保留"待真人测试"，在依据格追加"出声思考 n=5：k 人……"。

### 例子

| 设计决定 | 依据 | 证据等级 |
|---|---|---|
| 第 2 步橡皮一行：碰后 0.297、0.594 m/s，动能 0.053 J | check 块 `k_rub` | 已计算 |
| 五个错误想法每条都填了四格 | `check_spec.py` S5 | 已自动检查 |
| 第 1 步三选一并锁定，揭晓后不能改 | Crouch, Fagen, Callan & Mazur 2004, Am. J. Phys. 72, 835，只读摘要（美国大学生；只看演示的学生与没看的差不多） | 有研究支持 |
| C1"碰后弹开就是弹性碰撞，动能不变" | Bryce & MacMillan 2009, JRST 46(7)，只读摘要（学生默认碰撞时动能守恒）；"弹开 = 弹性"的具体说法：教学经验，待核 | 有研究支持 |
| C1 的"弹开 = 弹性"这个说法 | 教学经验，待核 | 待真人测试 |
| 带着 C2 的学生在第 6 步选"A 停下" | 走查记录 `walkthrough-C2` | 已模拟走查 |
| 第 6 步预估首答正确率 35% | 教学经验，待核 | 待真人测试 |

（例子里的条目号、记录名是示意，写真规格时换成真的。）

## 二、课件要记录的数据

写进规格的 `## 课件要记录的数据` 一节。每一项写明它回答什么问题，以及回答之后改规格的哪里。

| 数据 | 怎么记 | 回答什么问题 | 回答之后改哪里 |
|---|---|---|---|
| 每题首答正确率 | 每个 Choice 记第一次提交是否正确（预测题不判对错，不记） | 预估首答正确率（35%～70%，标准 §五.8）准不准？哪些题落在区间外？ | 校正题目表的预估列；低于下限的题回去补前面的铺垫，高于上限的题加难或删 |
| 各选项选择率 | 每个 Choice 的每个选项第一次被选的比例 | 每条错误想法是否真有学生持有？有没有选择率约为 0 的干扰项？有没有哪个错误选项比正确项还高？ | 错误想法清单的依据列从"待核"改成实测；换掉没人选的干扰项；选择率高的想法加一步推翻 |
| 提示用到第几级 | 每个带 `hints` 的题记最高用到第几级（0、1、2、3），和是否错两次后被揭示 | 三级提示（标准 §五.7）有用吗？第 3 级用得多，是前面没铺够，还是第 1、2 级提示没指对方向？ | 改提示；回头补相应的步 |
| 每步停留时间 | 每步从进入到离开的秒数，按学生记，报中位数 | 哪一步明显比别的久（可能一屏塞了两个想法，标准 §四.6）？哪一步几乎没停（可能没引起思考）？ | 拆步或并步；用来发现异常步，不用来排分钟（节奏用步数预算，标准 §三） |
| Recall 时预测对错 | 每个预测题记所选项是否就是 `correct` 那项，Recall 出现时再记一次是否改看 | 引出的情境是否真的引出了错误想法（预测错的比例太低，说明情境没引出）？学生看完证据后，结论是否留得住？ | 改引出情境；对照小测里同一想法对应选项的选择率 |

记录格式（建议；是否已有、怎么存，由规格注明"待派活核对"，本技能不改课件）：

```
{ lesson, learner, step, name, kind: "choice|predict|fill|lab", pickedFirst, correctFirst,
  attempts, hintLevelMax, revealed, dwellMs, recallPick, recallIsCorrect }
```

分析时先按"每题首答正确率 × 各选项选择率"画一张题—选项表，再对到错误想法清单。样本小时只看方向，不下显著性结论。

## 三、数值核对块

规格里每个计算得来的数，都要进 ```` ```check ```` 块，由 `check_numbers.py` 重算。读不到的数、估计的数（如"估计 40%"）不进。

### 格式

块内每行一条：

- `名字 = 表达式`：定义中间量。
- `名字 = 表达式 ≈ 值`：除了定义，还要核对：表达式算出的数，按"值"的小数位数四舍五入，必须等于"值"。
- `^` 是乘方；`#` 后是注释；名字可以引用前面定义过的名字；名字用字母、数字、下划线，不以数字开头。

### 例子一：第 2 步的数据表（来自 collision 规格）

````
```check
m1 = 0.4
m2 = 0.2
p_mag = m1*0.198 + m2*0.794 ≈ 0.238
k_mag = 0.5*m1*0.198^2 + 0.5*m2*0.794^2 ≈ 0.0709
r_mag = k_mag/0.072*100 ≈ 98.45
```
````

### 例子二：第 9 步示范例题（3 kg 的 A 以 4 m/s 弹性正碰静止的 1 kg 的 B）

````
```check
m1 = 3
m2 = 1
v1 = 4
u1 = (m1 - m2)/(m1 + m2)*v1 ≈ 2          # 碰后 A，向前为正
u2 = 2*m1/(m1 + m2)*v1 ≈ 6               # 碰后 B
p_before = m1*v1 ≈ 12
p_after = m1*u1 + m2*u2 ≈ 12            # 动量检验
k_before = 0.5*m1*v1^2 ≈ 24
k_after = 0.5*m1*u1^2 + 0.5*m2*u2^2 ≈ 24   # 动能检验
```
````

### 写法的要点

- 每个选项里的数、每个"（动量 6 = 3 + 3）"式的核对、每个损失百分比，都进块。
- 干扰项的数也进块：它是"按那条错误想法算出来的答案"，要能算出来（方法 10）。
- 一个块对应一个题或一张数据表，块前用一句话写明对应哪里。所有块共用一个名字空间，后定义的会覆盖同名的量，所以不同块里用不同的名字（如 `p_mag`、`p_rub`）。
- `≈` 后面的值要在规格正文里出现过，否则脚本给警告（可能写错，或正文没用上）。规格里正文写的数，和块里的"值"必须是同一个数。改了一处，另一处同步改，再跑脚本。
