# 设计一节课的规格

目标：每条设计决定都能回到一手证据，每份规格都能被我们俩以外的东西检验。**要做深，不做大**：本技能不新增设计规则，规则全在 `plans/lesson-design-standard.md`（下称"标准"），技能里引用它的节号。

产出是一份 `plans/lesson-<名>-spec.md`：照标准第八节的模板，加一张证据表、一节课件要记录的数据（这是对模板的补充，不是新规则），再附证据等级汇总和要用户定的事。写法的样子见 `plans/lesson-collision-spec.md`。

和 ux-scout 分工：界面、布局、配色、交互手感归 ux-scout；这一步教什么、问什么、让学生怎么想归本技能。一件事牵涉两边时，规格里写"要学生做出什么判断"，画面怎么摆留给 ux-scout。

和用户用中文交流。**不改组件库和课件**：规格定了、用户确认后再派活。

## 分工（按 CLAUDE.md）

主会话统筹，子代理干活。物理推导、预期数值、教学判断、`check` 块、定规格、最终验收主会话自己做。派活说明写明：只改哪些文件、不提交、做完跑哪些检查、交回什么。

| 活 | model | effort |
|---|---|---|
| 读课标、教材、论文、评卷报告原文，摘出处、位置、逐字引文和结论 | haiku | high |
| 把材料综合成做法卡，判断与现有方案是支持还是冲突 | haiku | xhigh |
| 跑 `check_spec.py`、`check_numbers.py`、`npm run verify`，交回原始输出 | haiku | medium |
| 按定好的规格整理证据表、补文案、更新表格 | haiku | medium |
| 盲评（第 5 步） | haiku | high |
| 模拟学生走查（第 5 步） | haiku | high |

子代理交回的是模型输出，不是证据。主会话抽查：引文回原文核对，数字自己重算。

## 第 0 步：把任务做深，不做大

动手前先针对**这一节课**写一段"深化说明"给用户看，回答四个问题，再把需求改写成任务说明。不写通用套话，每条都落到这节课上。

1. **顶尖的人会多做什么**：例如先去看学生实际怎么答（选项分布、评卷报告里的典型错误），而不是凭经验猜错误想法；从历年真题的标准解答里拆出熟手的判断序列；先写检验题再设计课；每条错误想法都去找一手研究。
2. **从哪些一手材料入手**：按第 2 步的分级，列出这节课要用的原始材料，和只当线索的材料。
3. **用哪些方法和工具**：方法要有名字、有步骤（`references/methods.md`），工具要能在本环境跑（见"工具"）。
4. **除了我们俩，还有什么能证明它对**：数值重算、自检脚本、盲评、模拟走查、研究原文、真人测试。写清这次哪些能做到，哪些要用户安排。

改写后的任务说明：

```
课名与教材位置：<例：弹性碰撞和非弹性碰撞（选择性必修第一册 第一章 第 5 节）>
课型：<新授 / 进阶 / 综合，见 plans/unit-momentum.md 第四节>
现状：<有无规格、有无课件（路径）；check_spec.py 的通过/不通过/查不了各几条>
要回答的问题：<2–4 个，可证伪。例：学生真的默认"弹开就是弹性"吗？这道题的第 3 个选项会有人选吗？>
一手材料：<清单，各标等级；拿不到的单列>
方法：<清单，取自 references/methods.md>
交付：<规格文件、证据表、课件要记录的数据、请用户定的事；要不要做真人测试单>
验收：<哪些检查必须过；盲评和走查的设置；要用户安排的真人测试>
不做：<明确排除的范围；本节留给哪节课>
```

用户确认或修改后再往下做。用户说"直接做"时，把任务说明写进规格的开头，照常往下做。

## 第 1 步：先审现状

复审时只需要两样输入：规格文件和课件路径（`lessons/*.md` 或 `mockups/<课>/`）。其余材料后面各步自己去找。

1. 对照标准第七节的自检清单，先跑脚本：
   ```
   python3 .claude/skills/lesson-design/scripts/check_spec.py plans/lesson-xxx-spec.md
   python3 .claude/skills/lesson-design/scripts/check_numbers.py plans/lesson-xxx-spec.md
   ```
   脚本输出逐条"通过 / 不通过 / 查不了"，不通过和查不了附行号与原因。跑脚本派 haiku medium，要原始输出，不要摘要。
2. "查不了"的条目（问题线是否因果相接、概念是否在事实之后才命名、删除检验等）由主会话自己逐条过，不派出去：这是教学判断。
3. 有课件的，把课件的步和规格问题线逐步对齐，列出不一致。标准第九节拿动量课做过一次这样的对照，照那个格式写。
4. 把规格里每条依据写着"教学经验，待核"的错误想法、每个没有来源的数字挑出来，它们是第 2 步要找的材料。
5. 输出缺口表，给用户看：

   | 第七节条目 | 状态 | 缺口 | 谁补、用什么材料补 |
   |---|---|---|---|

没有现成规格的新课：跳过脚本，只确认课标位置和单元位置（`plans/unit-momentum.md`），然后进第 2 步。

## 第 2 步：一手材料

按等级从高到低用。各来源的等级、本环境能否抓取见 `references/sources.md`。

| 级 | 材料 | 用来做什么 |
|---|---|---|
| 一手 1 | 课标、教材、教参原文 | 课标定位（标准 §二.1）。课标在 `references/curriculum/`，引用写主题编号和页码，标"读了原文" |
| 一手 2 | 学生作答数据：PhysPort 概念测试的选项分布、评卷报告的得分率和典型错误、库里 `survey/` 的真题 | 错误想法清单、选项诊断、难度预估。真题只有题和标准解答，没有得分率，别当作答数据用 |
| 一手 3 | 研究论文原文的**方法和数据部分** | 只读摘要的不算读过；引用处照实标 |
| 一手 4 | 名师课例的录像或逐字稿 | 问题线怎么排、一步放多少。Mister-Hope 逐字稿、国家中小学智慧教育平台课例 |
| 一手 5 | 真实实验数据、原典 | "数字有来处"（标准 §四.7）。库里第 1 节的"实测"是模拟数据，不算 |
| 线索 | 教学设计汇编、博客、AI 总结、教师指南的提示，**以及我们自己的设计标准** | 只用来决定去看哪里。不作为依据 |

规矩：

- 每条引用标"读了原文"或"只读摘要"。读到哪一页、哪个表，写位置。
- 拿不到的原文列成清单交给用户，让用户下载到 `.claude/skills/lesson-design/references/downloads/`（清单格式见 `references/sources.md` 末尾）。用户放进去之后，才把"只读摘要"改成"读了原文"。
- 本环境很多站点被代理拒绝，不要绕行；抓不到就列入"拿不到的原文"。
- 一个来源的做法不当规律：至少在两处独立见到，或有研究数据支撑，否则在规格里标"孤例"。
- 错误想法的"依据"一栏：有一手来源写来源和位置；没有就写"教学经验，待核"（collision 规格的做法），这条的证据等级只能是"待真人测试"。

读原文和摘出处、结论派 haiku high；交回必须带位置（页码、段、表号）和逐字引文。综合成做法卡、判断支持还是冲突派 haiku xhigh。做法卡的格式：

```
### <做法名>
- 出处：<作者年份、页或节；读了原文 / 只读摘要>
- 解决的问题：<学生遇到的什么困难>
- 机制：<为什么有效>
- 依赖的前提：<离开它就不成立的条件，如学段、人数、有无老师在场>
- 在我们这里：<落到规格哪一栏、哪个组件；与标准支持还是冲突>
```

## 第 3 步：按方法写规格

方法清单、出处、步骤、落到模板哪一栏、对应哪个组件，全在 `references/methods.md`。顺序：

1. **课标定位**：抄三栏（标准 §二.1），引用写主题编号和页码。
2. **逆向设计**：先写目标和检验它的题，再设计课（标准 §二.3）。
3. **认知任务分析**：从真题标准解答和教材例题拆出熟手的判断序列，决定目标、重点难点和示范例题的"策略"段。
4. **错误想法四格表**：每条填四格，依据一栏分级（标准 §二.5）。
5. **问题线表**：每一步填出"上一步留下的问题……这一步回答……留下……"，写"这一步要达成什么"，四段各定步数预算（标准 §三、§四）。节奏用步数，不用分钟。
6. **每条错误想法按引出—冲突—化解处理**，关键处用预测—观察—解释，预测要锁定（标准 §四 规则 2、3）。
7. **对比案例、渐退样例**用在巩固段（标准 §三 巩固段、§五.1、§五.4）。
8. **题目**：用 TIPERs 题型，错误选项对应错误想法，按选项诊断写反馈，标预估首答正确率（标准 §五）。
9. **数值**：规格里每个计算得来的数都进 ```` ```check ```` 块（写法见 `references/templates.md`）。主会话自己算，不派子代理估数。
10. 按标准第八节的模板排版，在"题目"之后、"自检"之前加 `## 证据表` 和 `## 课件要记录的数据` 两节。

规格里的结论区、作业、课件的幕与步等栏，照 `plans/lesson-collision-spec.md`（出处：标准 §四"结论区"、§五.10）。组件库不支持的题型，在规格里照写，注明"组件待定"，不去改库。

## 第 4 步：证据表与要记录的数据

1. **证据表**：每个设计决定一行，格式 `| 设计决定 | 依据 | 证据等级 |`。等级只能是六档之一：已计算、已自动检查、已盲评、已模拟走查、有研究支持、待真人测试。一行一档；同一决定有两种证据，写两行。各档的判定标准和例子见 `references/templates.md`。
2. 依据里引用外部材料的，必须标"读了原文"或"只读摘要"（`check_spec.py` 会查）。
3. **课件要记录的数据**：每题首答正确率、各选项选择率、提示用到第几级、每步停留时间、Recall 时预测对错。每项写明它回答什么问题，模板见 `references/templates.md`。记录功能现在有没有，由规格注明"待派活核对"，本技能不改课件。
4. 证据等级汇总：各档几条，其中"待真人测试"的单独列成一张表，它们就是"请用户定"和"请用户安排测试"的清单。

## 第 5 步：分层验证（除了你和我，还有什么能证明它对）

| 层 | 做法 | 谁做 | 算哪档 |
|---|---|---|---|
| 1 数值重算 | `check_numbers.py` 重算每个 `check` 块，全部相符 | `check` 块主会话写，脚本 haiku medium 跑 | 已计算 |
| 2 自检脚本 | `check_spec.py`：第七节里能机械查的条目 | haiku medium | 已自动检查 |
| 3 课件校验 | 课件做完后 `cd app && npm run verify` 全部通过 | haiku medium 跑，主会话看输出 | 已自动检查 |
| 4 盲评 | 新开子代理，只给标准和规格（去掉"证据表""自检"两节，不说哪份是新的、不给我们的结论），让它逐条过第七节并说理由；多份规格随机编号排序。它与我们不一致的地方写进报告 | haiku high | 已盲评 |
| 5 模拟学生走查 | 每条错误想法开一个子代理，只给它"你带着这条想法"和学生看得到的题、选项、反馈，逐步作答并说理由。对照规格"在哪一步推翻"是否吻合。**只算弱证据**，不用来估正确率 | haiku high | 已模拟走查 |
| 6 研究原文 | 第 2 步读到原文的方法和数据部分，且与设计决定一致 | haiku high 读，主会话抽查 | 有研究支持 |
| 7 真人测试 | `references/user-test.md` 三份测试单：学生出声思考、老师审读、前后测加延迟测。**由用户安排** | 用户 | 做完前一律"待真人测试" |

每一层的结果回填证据表。层 4、5 是模型输出：盲评与走查的结论与我们不一致时，不要为了过关而改盲评的设置，写进报告让用户看。

## 第 6 步：交付

- 规格写进 `plans/lesson-<名>-spec.md`，数值脚本和自检脚本都已跑过，输出附在报告里。
- 报告写成 HTML Artifact 发给用户，结构：
  1. 改写后的任务说明；
  2. 缺口表（复审时）；
  3. 材料清单，各标等级和"读了原文/只读摘要"，拿不到的单列；
  4. 规格（链接到文件）；
  5. 证据表和等级汇总；
  6. 验证结果（脚本输出、盲评、走查，及与我们不一致之处）；
  7. 请用户定的问题，和需要用户安排的真人测试。
- 聊天里只写结论和要用户定的事，不贴整份报告。
- 规格定了、用户确认后，才派活做课件；提交推送由主会话统一做（CLAUDE.md）。
- 课件上线有答题数据后，按"课件要记录的数据"校正预估首答正确率（标准 §五.8），并把错误想法的依据从"待核"改成实测。
- 用户否掉的做法，在规格里记下理由，下次别再端出来。

## 不要做

- 不要改组件库和课件。规格定了再派活。
- 不要把一个来源的做法当规律；孤例标"孤例"。
- 不要写套话目标（"体会探究过程"）。目标一律写成可检验的动词句（标准 §十）。
- 不要按分钟排时间；节奏用步数预算（标准 §三）。
- 不要新增设计规则。觉得标准缺一条，写进"请用户定的问题"，不要写进规格当作已定。
- 不要把设计标准、博客、AI 总结当依据；它们只是线索。
- 不要把"只读摘要"写成"读了原文"，不要编出处、页码和数字。拿不到的原文列出来。
- 不要把盲评和模拟走查当成真人证据。
- 不要靠心算或估数。规格里每个计算得来的数都进 `check` 块。
- 不要凭印象说"这样更好教"；给出证据等级。
- 子代理不提交、不推送。

## 工具

- `scripts/check_spec.py`：第七节清单里能机械查的条目，另查证据表的等级和依据标注。
- `scripts/check_numbers.py`：重算规格里所有 `check` 块。
- `references/curriculum/`：课标全文转写（`standard-2017-2025.md`，每页有 `<!-- p.N -->` 页码标记）和主题索引（`README.md`）。
- `references/sources.md`：一手材料分级清单、抓取实测、拿不到的原文。
- `references/methods.md`：十种方法。
- `references/templates.md`：证据表与六档判定、课件要记录的数据、数值核对块。
- `references/user-test.md`：真人测试单。
- `references/downloads/`：用户下载的原文放这里。
- `survey/`（真题调研，结构见 `survey/README.md`，全文在 `survey/text/<年>.txt`）、`plans/momentum-exam-2021-2025.md`、`plans/unit-momentum.md`、`plans/step-lesson-syntax.md`（组件清单）。
- `cd app && npx tsx scripts/genui.ts validate ../lessons/<文件>.md`、`cd app && npm run verify`。
- WebFetch / WebSearch：读原文。本环境多数站点被代理拒绝，实测见 `references/sources.md`。
- Agent：查文献、盲评、模拟走查、跑脚本（model 与 effort 见上表）。
